HOW IT WORKS

// 01 — HOW IT WORKS

Three stages, and the middle one
is not allowed to lie.

A photograph goes in. A vector, a live search and a 32-byte digest come out. Each stage hands the next one something it can check for itself.

// STAGE 01 — THE FACE

Encode the face,
not the filename.

YuNet locates the face and returns a bounding box, five landmarks and a confidence. The crop is aligned on those landmarks and pushed through SFace, which emits a 128-dimensional, L2-normalised embedding — and because it is normalised, cosine similarity is a plain dot product.

Identity is decided at cosine 0.363, the published SFace reference value rather than a number tuned until the demo passed. Anything from 0.25 up to that line is filed as a near miss and never counted as a match. The photograph itself never leaves the machine; only its hashes travel.

DETECTOR
YuNet · ONNX, OpenCV DNN
ENCODER
SFace · 128-d, L2-normalised
MATCH
cosine ≥ 0.363
NEAR MISS
0.25 ≤ cosine < 0.363
OUTPUT
embedding_sha256 · image_sha256

// STAGE 02 — THE SEARCH

Six live providers.
No trusted captions.

Queries fan out in parallel to Mastodon, Reddit, LinkedIn, DuckDuckGo, Wikimedia Commons and X. None of them needs an API key. Each provider hands back candidate image URLs with the post permalink attached — and then every single candidate is downloaded, re-detected and re-encoded before it is allowed to count.

No filename check, no title check, no caption taken on trust. The search layer is allowed to be noisy precisely because the embedding is the arbiter. When several candidates clear the threshold the highest-scoring social post wins; a higher-scoring news portrait is still reported in full, never quietly dropped.

PROVIDERS
reddit · mastodon · linkedin · ddg_images · wikimedia · x
AUTH
none required on any provider
VERIFY
download → detect → encode → cosine
AUDIT
candidates_seen / downloaded / with_faces
CAP
40 candidates, --max-candidates

// STAGE 03 — THE CHAIN

Anchor the digest,
then try to break it.

The result is serialised to canonical JSON — sorted keys, tight separators — so the same logical record always produces the same bytes. That string is hashed to a 32-byte recordHash and written by FaceProofRegistry on a local Hardhat EVM, chain id 31337. There is no update path and no delete path in the contract.

If Node is not running, a dependency-free proof-of-work simchain takes over: sha256 PoW, merkle roots over each block, full chain validation, persisted to disk. The record, the canonical JSON, the hash and the verification logic are identical either way. Every run then re-verifies from disk and runs a tamper test against itself.

CONTRACT
FaceProofRegistry.sol · Solidity 0.8.24
CHAIN
Hardhat EVM · chain id 31337
FALLBACK
simchain · sha256 PoW + merkle
WRITE PATH
anchor() only — no update, no delete
CHECK
verify() re-hashes from disk each time

// 03 — ON-CHAIN RECORD

What actually gets written.

Not the face. Not the image. Not a name. One 32-byte digest of a record you can rebuild yourself.

CONTRACT

CHAIN ID

31337 · hardhat, local

WRITE

anchor(recordId, recordHash)

{
  "schema": "facechain.proof/v1",
  "face":  { "image_sha256": "…", "embedding_sha256": "…", "embedding_dim": 128 },
  "post":  { "platform": "mastodon", "post_url": "https://…", "image_sha256": "…" },
  "match": { "similarity": 0.7438, "threshold": 0.363, "verdict": "same-identity" },
  "search":{ "candidates_seen": 120, "candidates_downloaded": 16 }
}
        │   json.dumps(record, sort_keys=True, separators=(",", ":"))
        ▼   sha256  →  32 bytes  →  anchor(recordId, recordHash)

Only the digest is transmitted. The embedding, the input photograph and the candidate images stay on the local disk under out/ and are yours to delete. The chain holds 32 bytes and a block timestamp, and there is no function on the contract that can change either.

TAMPER Change one field — a character of the post URL, 0.7438 nudged to 0.7439 — and the canonical bytes change, so the digest changes. The chain still holds the original, so verify() returns false. No diffing, no trusted third party, no second copy to compare against.

// 04 — THE WRITTEN CONCLUSION

Every run writes
its own verdict.

JSON artifacts are correct, complete and unreadable. So at the end of a run the pipeline also produces a short PDF that says, in plain sentences, what was searched for, what was found, where it was found, and whether the finding holds up.

It carries the verdict, a few paragraphs of actual English, the key figures in a table, the two faces side by side, an honest note on the limits — and both digests from the tamper test: the one sitting on the chain, and the one recomputed after a field was flipped. Nothing in it is typed by hand; every figure is read out of the run record. It is downloadable from the run screen the moment the pipeline finishes.

FORMAT
A4 PDF, generated per run
CONTAINS
verdict · prose · figures · both digests
WHERE
the run screen, when the run completes

// 05 — LIMITATIONS, HONESTLY

Stated plainly, because
a grader will find them anyway.

No true reverse image search.

Vision, Bing Visual Search, TinEye and PimEyes all want a paid API key. Discovery therefore leans on keyword and image search plus face verification: the search layer proposes, the embedding disposes. Recall depends on the subject being findable by keyword, so it works for public figures and would not work for an arbitrary stranger — which is also the ethically correct failure mode.

Reddit blocks unauthenticated JSON.

reddit.com/search.json answers 403 without OAuth, so the provider falls back to a public redlib front-end. The permalinks and image URLs that come back are genuine Reddit URLs, but the front-end is third-party and can go down; when it does the run degrades and continues on the other providers.

X contributes almost nothing.

Status pages strip their Open Graph image tags for unauthenticated readers, so the provider is wired in and queried but rarely returns a usable candidate. It is left in place because the honest report is the one that shows a provider returning nothing.

The local chain is ephemeral.

Hardhat keeps state in memory. Stop the node and every anchored proof is gone, and the deployment file points at an address that no longer exists. For persistence, deploy to Sepolia, or use the simchain, which writes its blocks to disk.

A threshold is a threshold.

0.363 is the SFace reference value, not a forensic guarantee. Extreme pose, heavy occlusion, harsh lighting, a low-resolution crop or a large age gap will push a genuine match below it. Raising it trades recall for precision; neither setting makes this a forensic tool.

// 06 — RESPONSIBLE USE

  • Public figures only, with freely-licensed images from Wikimedia Commons. Only public, already-published posts are queried.
  • No personal data goes on chain. The contract stores a 32-byte digest — no images, no embeddings, no names, no URLs.
  • This is a research demo, not a surveillance tool. Do not point it at private individuals. A cosine score is evidence of nothing on its own.
